## Anomalies

### HAT2-A1 — BLOQUANT : CRED-1 V1, en-têtes d'autorisation non détectés

Texte normatif (`credential_rules.CRED-1.indicators.V1`) : « en-tête d'autorisation dans une
valeur : « Authorization: … » ». L'implémentation n'accepte comme préfixe que début, espace,
`;` `,` `{` `"` `'`.

```text
S.artifact(provenance_metadata={"h": "Authorization: Bearer abc"})      -> rejeté
S.artifact(provenance_metadata={"h": "hdr=Authorization: Bearer abc"})  -> ACCEPTÉ
"(Authorization: Bearer abc)", "[Authorization: x]", "<Authorization: x>", "|Authorization: x" -> ACCEPTÉS
```

Idem dans les trois champs du périmètre. Contredit C02-INV-18 et la mention « CORRIGÉ » de
HAT-A2 dans le rapport CA-01.

### HAT2-A2 — BLOQUANT : contournement de P-03 et de C02-INV-09 par `artifact_id` dupliqué

`DatasetSnapshot.verify_artifacts` indexe les artefacts fournis dans un dict par
`artifact_id` : un doublon écrase silencieusement le précédent.

```text
validate_i01_snapshot(snap, calendar=cal, artifacts=[vrai])        -> 0 erreur, data_pass_eligible=True
validate_i01_snapshot(snap, calendar=cal, artifacts=[vrai, faux])  -> 1 erreur ("does not match its reference")
validate_i01_snapshot(snap, calendar=cal, artifacts=[faux, vrai])  -> 0 erreur, data_pass_eligible=True
snap.verify_artifacts([faux, vrai])                                -> accepté
```

`faux` porte le même `artifact_id` et un contenu différent. Le résultat dépend de l'ordre de la
liste. Le profil calcule en outre ses contrôles temporels (P-24) sur la liste fournie, donc
potentiellement sur l'artefact falsifié. Contredit P-03 (« artefacts fournis = références ») et
C02-INV-09 (« références = artefacts »).

### HAT2-A3 — BLOQUANT (formel, impact pratique faible) : format d'instant QCJ-1

QCJ-1 impose `"YYYY-MM-DDTHH:MM:SS.ffffffZ"`. Pour une année < 1000 :

```text
format_utc_datetime(datetime(999, 1, 1, tzinfo=UTC)) -> '999-01-01T00:00:00.000000Z'
```

Résultat dépendant de `strftime` (plateforme). Le même format est réutilisé par QCT-1. Aucune
donnée I01 n'est concernée, mais la forme canonique normative n'est pas respectée.

### HAT2-A4 — MINEUR : cas limites CRED-1 et QCT-1 non déclarés

- `redis://:pw@host` (utilisateur vide) accepté ; le texte V4 « utilisateur:motdepasse » est
  ambigu sur ce cas.
- V2 rejette `Basic Materials`, `Token Ring`, `bearer bond` : faux positifs non déclarés, alors
  que les limites affirment que V1–V4 « exigent une forme structurelle pour éviter les faux
  positifs sur du texte ».
- `format_decimal(Decimal("1e30"), 6)` lève `decimal.InvalidOperation` (et non `ValueError`) ;
  la limite de précision du contexte décimal n'est pas déclarée.

### HAT2-A5 — MINEUR : documentation de compatibilité inexacte

- BC-06 (« égalité avec un dict conservée ») et rapport CA-01 : faux dès que le mapping contient
  une liste — `rec.parameters == {"columns": [...]}` vaut `False` (vrai avec un tuple).
- BC-03 ne mentionne que le JSON ; `model_dump()` gagne aussi les clés v1.1. La phrase du rapport
  CA-01 « la compatibilité au niveau dictionnaire est conservée » est imprécise.

### HAT2-A6 — MINEUR : limitation C02-INV-05 trompeuse

La limitation affirme que « la conformité d'un objet s'établit par validation (model_validate) ».
Or un `TransformationRecord.model_construct(parameters={"api_key": "s3cr3t"})` inséré dans un
`DatasetSnapshot(...)` **validé** est accepté tel quel : `parameters` reste un `dict` mutable
contenant un secret. La validation du conteneur ne revalide pas les instances imbriquées.

## Réserves (sans effet sur le verdict)

- Contournements par attributs spéciaux (`__dict__`, `vars()`, `__setstate__`,
  `setattr(obj, "__class__", X)`) : relèvent des « contournements délibérés » déclarés, mais
  ne sont pas énumérés.
- V3 ne détecte pas `token=abc` sans délimiteur préalable ni `X-Amz-Signature` : conforme au
  texte, forme de fuite réaliste à considérer en CA-02.
- C02-INV-14 n'est vérifié que par `verify_calendar`, jamais à la construction ; il est vide si
  `canonical_range` est absent ou `expected_sessions` `UNKNOWN`.
- P-24 : acquisition antérieure à la dernière séance → simple avertissement.
- QCJ-1 tronque les microsecondes des heures locales (`HH:MM:SS`) : collision d'empreinte
  possible ; point de spécification.
