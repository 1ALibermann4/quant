## Principe

HAT #3 a montré que certaines propriétés C02 étaient encore définies par le comportement
accidentel de Python / Pydantic / regex. CA-03 impose des **représentations normalisées**
(UTC, UTF-8, scanner CRED-1 à règles séparées, gel profond de `Knowable`) et **borne**
INV-05 à l'état scientifique plutôt qu'à toute métadonnée interne Pydantic.

## Environnement

Ubuntu 24.04.4 LTS (WSL) · Python 3.12.3 · pydantic 2.13.5 · pytest 9.1.1 · PyYAML 6.0.3 ·
Hypothesis 6.x (groupe `dev` uniquement, propriétés de permutation / temps / Unicode /
canonicalisation). Base : `cf63d57`.

## Décision M9 (demandée explicitement)

Inventaire :

| Type | Coercition observée | Décision |
|------|---------------------|----------|
| booléen scientifique (`survivorship_bias_acknowledged`, …) | `"yes"`→`True`, `1`→`True` | **Strict** — change l'ACK |
| entier scientifique (comptages, `byte_size`, `step_index`) | `True`→`1`, `1.0`→`1` | **Strict** — change gates / profondeur I01 |
| instant | str ISO → datetime | **Conservé** (JSON) |
| date | str ISO → date | **Conservé** |
| enum | str → membre | **Conservé** (JSON) |
| identifiant | aucune coercition utile | chaînes, domaine UTF-8 |

Un `strict=True` modèle-entier casserait `str`→datetime. La politique est donc **sélective**.

- ordre QCT-1 datetime = ordre des UTC.
