## Compatibilité (trois axes, vérifiés séparément)

| Axe | Méthode | Résultat |

| JSON canonique et sérialisé | SHA-256 de `model_dump_json()` de 5 objets (snapshot v1.1, snapshot v1.0, artefact, calendrier, évaluation) capturés à `3c684b7`, épinglés dans les tests | **Identique** |
| Empreintes | `fingerprint`, `raw_fingerprint`, `lineage_fingerprint`, 2 `application_key`, `content_fingerprint` du calendrier, épinglés ; 3 vecteurs canoniques | **Identiques** |
| Objets Python / API | Types en mémoire comparés avant et après | **Non totalement compatible**, voir ci-dessous |

Les différences Python introduites par CA-01 sont les suivantes :

- `instruments`, `adjustments` et `quality_flags` sont des `tuple`. `snap.instruments == ["X"]` devient faux.
- Les mappings v1.1 sont des `FrozenMap` : `isinstance(…, dict)` est faux, mais l'égalité avec un `dict` est conservée. Leurs listes internes sont des `tuple`.
- `assessment.snapshot_ref` n'est plus égal, au sens de pydantic, à une `DatasetSnapshotRef` C01 de mêmes valeurs ; `isinstance` reste vrai.
- `model_dump()` restitue toujours des `list` et des `dict` : la compatibilité au niveau dictionnaire est conservée.

**Décision** (consignée dans `compatibility.behaviour_changes_rationale`) : ces changements
suppriment des capacités de mutation que la postcondition v1.0 « snapshot immutable after publish »
interdisait déjà. Ils corrigent un défaut d'implémentation, pas le contrat. La version reste 1.1
(MINOR) et la politique de version n'est pas modifiée. Une sérialisation identique n'est **pas**
présentée comme une compatibilité Python totale.
