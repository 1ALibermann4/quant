## Anomalies

### HAT-A1 — BLOQUANT : C02-INV-05 (immuabilité) violé en profondeur

Le rapport déclare C02-INV-05 PASS. Mais `frozen=True` ne gèle que l'affectation des attributs de
premier niveau. Constats de la sonde sur `synthetic_snapshot()` et `artifact()` :

| Mutation après validation | Résultat |
|---------------------------|----------|
| `snap.provenance.time_range_end = 2030-01-01` | acceptée (`Provenance` n'est pas gelé) |
| `snap.instruments.append("OTHER")` | acceptée (liste) |
| `snap.lineage[0].parameters["date_rule"] = "tampered"` | acceptée ; **`snap.lineage_fingerprint` change** |
| `art.request_parameters["apiKey"] = "SECRET"` | acceptée ; contourne C02-INV-18 |

Aucun validateur n'est rejoué après ces mutations. Un snapshot « immuable » peut donc changer de
lignée, de bornes de provenance ou de métadonnées d'acquisition sans changer de `snapshot_id`,
contrairement à C02-INV-05 et REV-D-02. La limitation déclarée dans le YAML ne mentionne que les
listes v1.0 ; elle ne couvre ni `Provenance`, ni `AdjustmentRecord`, ni les dictionnaires
`parameters`, `request_parameters` et `provenance_metadata`.

### HAT-A2 — MAJEUR : C02-INV-18 (aucun secret) seulement vérifié sur les clés

La détection porte sur les **noms de clés**. Des secrets placés dans les **valeurs** sont acceptés :
`provenance_metadata={"h": "Authorization: Bearer abc"}` et
`request_parameters={"url": "https://x/?token=abc"}`. L'invariant tel qu'il est rédigé
(« aucun secret enregistré ») n'est pas garanti ; la garantie réelle est plus faible et n'est pas
documentée. Voir aussi HAT-A1, dernier cas.

### HAT-A3 — MINEUR : changements de comportement non déclarés

Le rapport indique comme « seul changement de comportement » le gel de `DatasetSnapshot`. Or, par
rapport au code v1.0 (`9a10d9b`) :

- la valeur par défaut de `contract_version` passe de `"1.0"` à `"1.1"`. Un objet construit en
  Python sans version explicite est désormais étiqueté 1.1. La garantie YAML « conserve sa valeur
  "1.0" » ne vaut que pour les objets qui la portent explicitement ;
- `contract_version` était libre en v1.0 ; il est désormais restreint à `{"1.0", "1.1"}`.

Les deux changements sont défendables, mais ils ne sont pas déclarés.

### HAT-A4 — MINEUR : couverture des tests du profil surévaluée

Le rapport affirme : « variantes non conformes pour chaque règle REQUIRED ». Faux : les tests
committés ne couvrent pas P-05, P-07, P-11, P-14, P-15, P-16, P-17, P-23, les détails de P-02 et
les branches `NOT_APPLICABLE` de P-04 et P-13 ; P-01 et P-03 ne sont vérifiés qu'indirectement ;
la branche BELOW_TECHNICAL de A-05 n'est pas testée. La **sonde** montre que le comportement de
toutes ces règles est conforme au profil (erreur, inconnue bloquante ou éligibilité comme
spécifié). Le défaut porte sur la preuve, pas sur le comportement.

### HAT-A5 — MINEUR : C02-INV-14 partiellement testé

Les tests ne couvrent ni le désaccord entre `canonical_timezone` et le fuseau du calendrier, ni une
borne canonique qui ne serait pas une séance. La sonde confirme le rejet dans le premier cas ; le
second n'est pas vérifié.

## Verdict

**FAIL.** HAT-A1 contredit un PASS déclaré sur un invariant normatif (C02-INV-05), et HAT-A2 un
second (C02-INV-18). Le rapport `97cb50b` ne peut pas être accepté en l'état. C02 v1.1 **n'est pas
clôturé**.

Les dossiers de sourcing (DR-003 v1.1, charte DR-005) ne sont **pas ouverts**, conformément à
l'ordre fixé : ils suivent un HAT PASS.
