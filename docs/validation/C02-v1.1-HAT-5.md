## A — Qualification profonde `T → wrapper`

### A1 / A2 — voies et matrice adversariale

Sur `Knowable[int]` et `Knowable[bool]`, rejet observé pour les bruts :

`True` / `False` (vers int), `0` / `1` / `-1` (vers bool), `0.0` / `1.0`, `"0"` / `"1"`,
`"true"` / `"false"` / `"yes"` / `"no"`, `Decimal(1)`, `bytes`, `complex`, `None` (INV-K01).

Voies : `.known()`, constructeur, `model_validate`, `model_validate_json`, champ parent
(`ObservationCounts`, `LicenseRef`, `TransformationRecord`), `tuple[Knowable[int]]`,
`FrozenMapping[Knowable[int]]`.

JSON :

| Entrée | Résultat |
|--------|----------|
| `Knowable[int]` ← `1` | accepté, `type is int` |
| `Knowable[int]` ← `true` / `1.0` / `1e2` | rejeté |
| `Knowable[bool]` ← `true` | accepté, `type is bool` |
| `Knowable[bool]` ← `1` | rejeté |

`Knowable.known(True)` **non paramétré** injecté dans `expected_sessions: Knowable[int]`
est rejeté à la revalidation (chemin HAT #4).

Hypothesis indépendant (générateurs distincts de CA-04, 80+80 exemples) : aucun accept
dont `type(value)` n'est pas exactement `int` / `bool`.

### Faux positifs écartés

Un premier script a classé **BLOCKING** deux cas JSON. Reproduction indépendante :

1. `json.dumps(IntEnum.ONE)` produit `1` — le JSON a déjà perdu l'enum ; valider ce JSON
   comme `Knowable[int]` est le chemin légal du nombre `1`, pas une coercition de wrapper.
2. La condition « JSON `1` / `true` légaux » était inversée dans le script.

`Knowable[int].known(IntEnum.ONE)` est **rejeté** (`type is` l'enum). En isolation,
`Field(strict=True)` **accepte** encore un `IntEnum` (comportement Pydantic antérieur à
CA-04). Le wrapper n'est donc **pas plus permissif** que T ; il est plus strict. Hors
périmètre d'une régression CA-04 ; pas une violation de BC-14 transitif.

Un second script (agent parallèle) a classé **BLOCKING** `A-CONTAINER-FROZENMAP` :
`ContainerInt(mapped=FrozenMap({'k': {'status':'KNOWN','value':True}}))` accepté.
Reproduction indépendante : le champ sondé était annoté `FrozenMap | None`, **pas**
`FrozenMapping[Knowable[int]]` — le schéma de sérialisation CA-04 de `FrozenMap`
accepte un mapping quelconque, sans prétendre valider `Knowable[int]`. Avec le
type conteneur correct, `True` est rejeté ; `request_parameters` / `parameters`
rejettent un `FrozenMap` illicite comme un `dict` (nested scalaire, CRED-1, float).
Non retenu.

## B — Mapping récursif / M1–M2

Chaîne `mapping imbriqué → freeze → model_dump → JSON → validate → QCJ-1 → application_key`
conservée (y compris listes d'objets et booléens internes).

CRED-1 à profondeur : `{"window":{"api_key":…}}`, Bearer en valeur, `user:pass@host`,
Bearer en élément de liste — tous rejetés. Un secret n'est pas invisible parce qu'il
est dans un mapping désormais autorisé.

`request_parameters` reste scalaire : un objet imbriqué est rejeté.

## C — Strictness × canonicalisation

Propriété centrale tenue :

- on ne peut pas valider à la fois `True` et `1` comme `Knowable[int]` ;
- `False` / `0` idem pour `Knowable[int]` / `Knowable[bool]` ;
- `Knowable.known(1.0).model_dump()` puis `Knowable[int].model_validate` est rejeté ;
- le JSON officiel de `Knowable[int](1)` ne valide pas comme `Knowable[bool]`, et
  réciproquement pour `true` ;
- `known("yes")` et `known(True)` ne deviennent pas des `LicenseRef` égales.
