## Persistence, atomicity, recovery

The parent receives a result, validates the expected cell ID/status, hashes the serialized record, atomically writes and fsyncs one `ckpt/<sha256(cell_key)>.json`, then appends and fsyncs `results.jsonl`, then updates durable-cell progress in `progress.json`. Workers never write canonical artifacts. At restart, checkpoint files and their record hashes, names, cell IDs and scientific config hashes are validated; temporary partial files are ignored; results.jsonl is atomically reconstructed from checkpoints in canonical order (including if its tail was truncated). A corrupt checkpoint fails closed. A checkpoint committed before a crash, even if its JSONL append was interrupted, remains authoritative and is restored on resume. Full completion requires equality of durable IDs and all expected IDs; unexpected/duplicate IDs are rejected. In-flight uncommitted cells alone can be lost. On Windows, file fsync and atomic replacement are used; Python does not expose a reliable directory fsync, so this is a process-crash/power-loss **analogue**, not proof against physical loss of storage-controller caches.

The first manifest records UUID run_id, UTC creation time, HEAD, scientific config hash, seed version, generator/oracle spec version, expanded geometry specs, environment and worker count. Resume checks code HEAD, scientific hash, seed contract, generator/oracle version, expanded specs and exact count before scheduling the missing set. `technical_failures.json` durably stores failed cell/exception/traceback; `FAILED_TECHNICAL` is not considered completed, and the manifest cannot become COMPLETE with failures. Existing completed checkpoints remain available.

## Empirical HAT and regression

A real Windows fresh-interpreter helper invokes the production `run_calibration` engine on eight real G0 cells: two worlds, two realizations and W=20/40. The parent-only progress, JSONL and checkpoint directory grew while workers were still running. In one run, 3 durable cells survived an abrupt process-tree kill (workers 4→1); in the reverse, 2 survived (workers 1→4). After resume, both produced 8/8 distinct expected cells, no duplicates, zero technical failures, no missing or unexpected cells; checkpoint modification timestamps for pre-crash cells did not change. Final results equaled independent uninterrupted single-worker references. The separate HAT invocation of these two cases passed (2/2, 221.92 s); this is a bounded execution-reliability HAT, **not** a repeat of the earlier scientific/performance HAT across geometry families.

The complete I04-CAL regression ran after the final code/test changes: **48 passed, 0 failed in 372.35 s**. Breakdown: test_cache.py 5, test_governance_invariants.py 12, test_hat_infra.py 2, test_l1_core.py 13, test_l2_adversarial.py 7, test_multiprocessing.py 3, test_exec03.py 6. New tests cover 12,096 IDs, golden seeds, hash-seed independence, per-cell progress, crash/restart in both worker directions, reference equivalence, no checkpoint rewrites, partial JSONL tail recovery, checksum tampering rejection, config mismatch rejection, and persisted worker failure diagnostics. Existing native spawn/determinism and checkpoint tests also pass.
